# CodeSec-Agent 全项目路线图设计

## 目标

将已经完成的 PR-Agent 双入口验证扩展为可复现、证据优先的安全审计链路：扫描发现、统一 finding、风险分析、Markdown 报告和 CI/PR 摘要。所有工作先保留在本地 Git 分支与 worktree，不推送 GitHub，除非用户在未来单独授权。

## 当前基线

- GitHub Actions PR-Agent + DeepSeek 自动审查已验证。
- Windows 本地 PR-Agent CLI + DeepSeek + 最小权限 PAT 已验证。
- 验证 PR、探针、验证分支和临时 worktree 已清理。
- Semgrep 已有设计与详细实施计划，位于本地 `codex/semgrep-phase3-plan` 分支；尚未创建扫描代码或执行真实扫描。

## 总体架构

```text
仓库或 PR 变更
  -> PR-Agent（已验证的上下文审查）
  -> Semgrep / Bandit / npm audit（可复现证据）
  -> 统一 finding 文档（稳定输入契约）
  -> 安全分析 Agent（解释、影响与修复建议）
  -> Markdown 报告（摘要与明细）
  -> CI 产物与 PR 摘要（默认只提示）
```

每个箭头之间都以文件化、可序列化的数据契约衔接。后续扫描器和报告消费者不得直接依赖某一扫描器的原始 JSON。

## 阶段与依赖

### 阶段 A：Semgrep 最小闭环

实现现有 Semgrep 设计：固定 CLI 版本、执行 `p/security-audit`、保存原始 JSON、归一化为 schema `1.0` finding 文档，并在当前仓库完成一次真实扫描。

完成标准：离线 fixture 契约测试通过；真实扫描生成可解析的原始与归一化 JSON；产物被忽略且不含凭据；不新增 CI、PR 评论、DeepSeek 调用或阻断行为。

### 阶段 B：扫描器适配器扩展

先接入 Bandit，再接入 npm audit。每个适配器独立读取自己的 JSON、映射为既有 finding schema，并保留原始引用。新适配器不得更改 Semgrep 适配器的语义；不兼容变化必须升级 schema 版本并提供迁移说明。

完成标准：每个适配器有一组代表性 JSON fixture、一个真实本地扫描、以及与 Semgrep 相同的输出 schema 验证。

### 阶段 C：安全分析 Agent

将统一 finding、最少必要的代码上下文和受控的 CWE/OWASP 参考传给 Agent。输出必须区分确认问题、可疑模式和可能误报，引用证据，并提供防御性修复建议；不输出利用步骤，也不自动修改代码。

完成标准：使用离线 finding fixture 生成结构正确的 Markdown 分析；对一个真实扫描结果进行人工质量复核；输入中没有凭据或敏感业务数据。

### 阶段 D：Markdown 审计报告

生成稳定报告，包括元数据、扫描摘要、严重级别统计、发现明细、证据、影响、修复建议和参考。报告生成器只消费统一 finding 与 Agent 分析结果，不调用扫描器或模型。

完成标准：最小、空结果和多扫描器结果均能生成可读 Markdown；提交一份无敏感数据的示例报告；报告字段有文档说明。

### 阶段 E：CI 与 PR 集成

新增独立安全扫描 workflow，保存原始 JSON、finding JSON 与报告为构建产物，并在 PR 发布简短摘要。初始策略只提示，不阻断合并；风险阈值在有真实误报数据后再单独决定。

完成标准：同仓库非 Bot PR 成功运行；产物可下载；摘要不暴露凭据或完整敏感代码；失败只由扫描基础设施错误触发，而不是发现本身。

### 阶段 F：可选增强

按独立子项目评估并实施：CWE/OWASP 本地知识库、误报治理、多语言规则策略、RAG、Word/PDF 导出和可视化界面。它们不阻塞阶段 A–E。

## 风险驱动验证策略

测试的目的仅是证明边界与回归风险，不追求覆盖率指标。

| 层级 | 必做验证 | 不做的验证 |
| --- | --- | --- |
| 纯转换器 | 每种输入格式的一组代表性 fixture：正常、空结果、缺失必填字段 | 为每个可选 JSON 字段建立单独测试 |
| 外部 CLI 封装 | 模拟子进程的成功、发现和基础设施失败路径 | 在每次本地改动都运行真实网络扫描 |
| 阶段集成 | 每个阶段一次真实、无敏感数据的端到端验证 | 为每个小提交重复执行完整链路 |
| Agent/报告 | 一个结构契约 fixture + 一个经人工复核的真实样本 | 对自然语言措辞做脆弱的逐字快照断言 |
| CI | 合并前一次同仓库测试 PR 验证 | 初版跨 Fork、阻断合并或并行所有扫描器 |

当发生以下变化时才增加测试：引入新数据契约、修复回归、接入外部工具的新失败模式，或发现真实误报/漏报。文档修改只进行链接与格式检查；不为文档创建业务测试。

## 本地工作规则

- 每个阶段在独立本地 worktree 分支实施，提交可审阅但不推送。
- 每阶段完成后先报告：实现范围、最小验证结果、剩余风险与下一阶段依赖。
- 不读取、回显或提交 API Key、PAT、扫描产物中的敏感内容。
- Bandit 和 npm audit 必须在 Semgrep 的真实验收完成后再开始。
- 合并阻断、远端 workflow 写入、PR 评论及任何真实模型调用需要用户在当时单独授权。

## 里程碑顺序

`A Semgrep -> B Bandit -> B npm audit -> C Agent -> D Markdown 报告 -> E CI/PR 集成 -> F 可选增强`

任何阶段若未达到完成标准，只修复该阶段的最小阻塞点，不提前搬运后续功能。
